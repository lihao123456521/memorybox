# 运行架构 · v0.4.0

本文描述当前源码中的职责和数据流。实现与验证分列，实际通过项以 [验证记录](verification.md) 为准。

React 状态机管理现实空间、模板采访、事实确认、穿越、探索、决定、写信与回归。Three.js 在同一应用中渲染真实几何体；UI 叙事层只覆盖必要的引导和信纸。物件状态与镜头聚焦分离，重玩不删除收藏。

前端先使用本地模板保证零 Key 可运行。FastAPI 提供模板、结构化叙事、回忆和信件 API，SQLite 保存用户主动确认的记录。浏览器随机凭据限制记录访问；后端使用参数化查询和外键约束。网络失败时前端明确提示离线模式，保留可继续的草稿。

资产来源集中记录在 manifest。五房间老屋采用以米为单位的网格、本地 PBR 与 CC0 家具；独立车站含候车厅、站台和可进入的车厢，独立教室含课桌与走廊。四类人物继续使用 MakeHuman CC0 人体、衣物、发型和五官。v0.4 先生成并查看四套虚构人物的多视角参考，再做参数拟合、局部几何调整和原 UV 材质烘焙；这不是自动图片转 3D、摄影测量或精确身份重建。原图、提示词与方法见 [人物参考与材质](character-reference-materials-v5.md)。

`WorldLayout` 给每套空间提供出生点、总览相机、区域并集、物件锚点和碰撞体。移动控制器检查玩家圆形占地与区域并集，在门洞中通行并沿墙滑动；总览和物件近景保留玩家先前的位置。叙事物件保留稳定ID以恢复原有收藏，界面按模板显示对应名称。

`WalkController` 区分第一人称、第三人称和总览。第一人称使用人眼高度与拖动环顾；第三人称围绕同一玩家位置跟随，按碰撞区域缩回镜头；总览使用独立观察相机。`playerAvatar` 与 `companion` 是两个独立选择，分别保存到浏览器偏好。第三人称在探索阶段显示自身人物，物品聚焦、人物预览与分支演绎各有镜头安排，不承诺所有阶段始终显示两个完整人物。

`HumanRig` 在原连续表面上生成运行时蒙皮：21 根骨骼、每顶点最多四个权重，实例拥有独立骨骼与材质参数；相同源几何和 URL 贴图按缓存复用。`idle / walk / wave / talk` 是程序动作，步态按腿长和脚部轨迹计算；角色路径由移动控制器或故事动作层控制。没有手指 / 面部表情骨骼、动作捕捉、口型同步、布料物理或任意地形接触保证。站姿 / 坐姿资产与裙装动作须分别做实际渲染验收。

`NarrativeClock` 驱动共享故事时间、播放状态和重播修订号。`StoryPlayback` 控制暂停、继续与重播，并突出当前字幕段；`StoryActions` 由该时间计算人物转身、沿通路移动、停步和挥手。真实分支的离开动作受已确认选择约束，不匹配离开事实时维持中性陪伴。车站用同一时间计算滑门、发车信号、列车位移和车轮角度；这些是艺术化预定动作，不是轨道交通物理仿真。`LocalTelevision` 生成原创 Canvas 动画并作为电视屏幕纹理，随时钟播放 / 暂停，不加载真实历史录像或外部视频服务。

现实空间使用珠贝胡桃木八音盒，包含独立铰链盒盖、椭圆平面镜、绒布托盘、凹入式机芯观察窗、销钉圆筒、梳齿、齿轮和旋转水晶玫瑰。穿越时花瓣时空门展开，镜头沿曲线靠近；加载遮罩覆盖场景，所选世界准备好后再揭开，加载较慢时继续等待。减少动态模式同样等待世界准备好并缩减装饰动画。此处是原创视觉实现，不声明机械制造或精确啮合仿真。`Lux3DProvider` 只保留接入边界，不建立收费任务，也不伪造任务成功。

根目录 `index.html` 是独立离线交付物，内嵌代码、样式和全部运行素材，`file://` 不请求后端，收藏保存在当前浏览器。公开 GitHub 仓库供下载与源码协作，不含个人内容；开发时才需要运行 HTTP 前后端。第三方照片上传没有启用。

当前 v0.4 单文件内嵌 62 项资源；字节数、素材哈希见 [构建记录](portable-build-v0.4.0.json)，公开发布与匿名下载结果见验证记录。
